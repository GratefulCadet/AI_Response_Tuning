# 저장소 의도 (Intent)

> 작성일: 2026-10-15 · 작성 근거: 채팅에서 사용자가 직접 전달한 의도

## 목적

GitHub 저장소 `AI_Response_Tuning`에서 AI에게 전달하는 "응답 프로필(응답 지침 프롬프트)"을,
**용도에 따라 답변이 어떻게 나오는지 튜닝**하기 위한 자료를 저장소 하위에 용도별로 정리한다.

핵심 질문:

- 어떤 용도(학습, 시험 풀이, 연구 조사, 개발, 글쓰기 등)에 대해서는 어떤 응답 방식을 지시해야 하는가?
- 그 지시가 실제로 인간이 이해하기 좋은 답변을 만들어내는가?
- 각 용도별 지침을 어떻게 반복해서 테스트하고 개선할 수 있는가?

## 기준 프로필

이 프로젝트의 출발점은 사용자가 채팅에서 직접 전달한 **개인 응답 프로필**이다.
문서 작성 기준상 원문 전체를 이 저장소에 그대로 저장하지 않고, 핵심 원칙만 요약해 두었다.
전체 원문이 필요하면 사용자에게 다시 전달받는다.

핵심 원칙 요약:

| 영역 | 핵심 요령 |
|---|---|
| 언어·말투 | 기본 한국어, 확신 없는 내용을 확정적으로 쓰지 않기, 원문 병기 |
| 설명 순서 | 결론 → 직관적 설명 → 배경/예시 → 정확한 정의와 원리 → 용어 연결 → 적용 방법 |
| 용어 | 전문 용어를 먼저 나열하지 않기. 쉬운 뜻을 먼저 설명하고 용어로 연결 |
| 형식 | 복잡하면 제목/소제목, 비교는 표, 코드·명령어·완성 문서는 복사 가능한 코드 블록 |
| 후속 질문 | 정보성 답변 끝에 "다음에 물어볼 법한 질문 2 + 이해 확인 질문 3 + 관점 확장 질문 2" 순서, 각각 독립 코드 블록 |
| 학습 지원 | 짧은 설명 → 문제 하나 → 사용자 답변 → 즉시 피드백 반복. 한 번에 여러 문제 출제하지 않기 |
| 코드 설명 | 큰 그림 → 쉬운 비유 → 실제 실행 흐름 → 덩어리별 역할 → 기술적 원리 → 프로젝트 적용 |
| 정답 확인 | 정답을 먼저 제시하고, 필요할 때만 짧은 근거 |
| 연구 | 원본 자료 기반, 주장과 해석·실험과 해석 구분, 검증 안 된 것은 가설로 표시 |
| 개발 | 목표·완료 조건 정리 → 최소 변경 → 실제 테스트 → 확인 못 한 것은 미확인으로 보고 |
| 글쓰기 | 사용자 관점과 자연스러운 말투 유지, 복사 가능한 완성형 결과물 |

## 진행 방향

1. **사전 조사** — 현행 논문·연구에서 "인간이 이해하기 좋은 LLM 답변"을 얻기 위한
   요청 방식이 무엇인지 정리한다. → `02-prior-research.md`
2. **용도별 프로필 정리** — 저장소 하위에 용도별 디렉터리와 프로필 문서를 만든다.
   예: `profiles/learning.md`, `profiles/exam.md`, `profiles/research.md`, `profiles/dev.md`, `profiles/writing.md`
   (실제 구조는 사전 조사 결과를 보고 사용자와 함께 확정)
3. **테스트·개선 루프** — 각 프로필을 실제 대화에 적용해 보고, 결과와 수정 사항을
   용도 디렉터리 아래에 기록해 반복 개선한다.
